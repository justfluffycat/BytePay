About BytePay

What is BytePay?

BytePay is a simple payment network that runs on a small Node.js server. It keeps a ledger of account balances and records every transfer inside a blockchain, so the history of payments can always be inspected and verified.

🏦

Accounts

Create an account and receive a unique by1 address derived from your public key, plus a small starting balance.

💸

Transfers

Send coins to any other BytePay address. Amounts are whole numbers, so there are no rounding errors.

⛓️

Blockchain ledger

Transactions are grouped into blocks of three. Each block stores the hash of the previous one, forming a tamper-evident chain.

Features

Built to be simple and safe

BytePay keeps the design small, but the core rules of a payment system are enforced on every request.

✍️

Signed transactions

Only the owner of the private key can spend from an address. Each transfer carries an Ed25519 signature that the server verifies.

🔁

Replay protection

Every account has a nonce that must increase by exactly one, so a signed transaction can never be submitted twice.

✅

Strict validation

Amounts must be positive integers, both accounts must exist, and the sender must have enough balance.

🚰

Rate-limited faucet

New accounts receive 10 starting coins. Account creation is limited to one per IP address per minute to prevent abuse.

🔍

Chain validation

A built-in endpoint re-computes every block hash and checks the links between blocks to detect tampering.

⚡

Lightweight

One file, two dependencies, zero setup. BytePay runs anywhere Node.js runs, in a single process.

How it works

From account to block in five steps

Here is what happens when someone uses BytePay.

Create an account

A key pair is created, and the address is generated from the public key. The account starts with 10 coins.

Sign a transaction

The sender signs the message from:to:amount:nonce with their private key.

The server verifies it

BytePay checks the signature, the nonce, the amount, and the sender's balance before accepting anything.

Balances are updated

Coins move from the sender to the recipient, and the transaction joins the pending list.

A block is created

Once three transactions are pending, they are sealed into a new block linked to the previous block by its hash.

Address format

Every address starts with by1

A BytePay address is the prefix by1 followed by 40 hexadecimal characters taken from the SHA-256 hash of the account's public key. That means an address can't be chosen or faked without the matching key, and typos are easy to spot because the prefix is always the same.

Example address by19f3a7c21b84e05d6a1c3f7e2908b4d5c61a7e3f0
API reference

Available endpoints

BytePay exposes a small JSON API.

EndpointDescription
POST/createCreate a new account and receive the starting balance.
POST/sendSend coins using a signed transaction.
GET/balance/:addressCheck the balance of an address.
GET/nonce/:addressGet the next nonce to use for an address.
GET/chainView all blocks and pending transactions.
GET/validateVerify the integrity of the blockchain.

Good to know

  • BytePay is a learning and demo project, not a real-world currency.
  • Data is stored in memory, so balances and blocks reset whenever the server restarts.
  • Never share your private key. Anyone who has it can spend your coins.
